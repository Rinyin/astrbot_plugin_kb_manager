# 知识库自主运维（astrbot_plugin_kb_manager）

让 AstrBot 在**正常对话**中自主维护 AstrBot 原生知识库：每次正常 LLM 请求都会注入一段可配置的 SYSTEM 维护规则，并把本插件当前已启用的工具提供给模型；模型据此在**每一轮对话中独立判断**本轮是否包含值得长期保留的专业知识——有就直接写入最相关的知识库、按证据纠正既有结论，必要时自主新建知识库。整个过程**不需要用户发起任何维护指令，也没有任何确认步骤**，任何发送者都可以让模型自主判断与维护。

仓库地址：<https://github.com/Rinyin/astrbot_plugin_kb_manager>

本文档对应插件版本 `0.2.0`。

## 工作机制（自主维护）

1. **每轮独立判断**：AstrBot 每次产生正常 LLM 请求时都会注入 SYSTEM 维护规则；模型先评估本轮内容的价值与可靠性，再决定是否维护知识库，不依赖任何外部触发。
2. **定位相关库**：用 `kbm_list_kbs` 找到与当前知识最相关的既有知识库。
3. **检索去重**：用 `kbm_search` / `kbm_list_documents` / `kbm_read_document` 检查是否已有相同或相近内容，已有足够内容就不重复写入。
4. **主动写入 / 纠错 / 建库**：把整理后的知识写入最相关的库；有可靠证据时更新原分块、整篇替换或删除过时内容；确实没有合适归属时才用 `kbm_create_kb` 新建。
5. **后台写任务**：写操作经后台任务执行，`request_id` 保证幂等；超过等待时间会返回 `job_id`，可用 `kbm_job_status` 查询进度。
6. **隔离与一致性**：任务与附件按“同一会话（UMO）+ 同一发送者”隔离；索引一致性语义见「行为与边界」。

说明：本插件的自动化测试验证的是 SYSTEM 注入、工具接线、会话隔离与写任务等机制；模型每轮自主判断的质量取决于所用模型与 `autonomy_system_prompt`，不由脚本化测试保证。

### 典型场景（自主维护，无需命令）

- 群聊里某类工具在特定场景下的排障经验，且上下文证据支持其可靠：模型判断其长期有用后，先检索相关库确认没有重复，再把结论整理成简洁文本写入最相关的库；没有合适归属时自主新建；已有带证据的相反结论时用新版本纠正；同一次写入重试时复用同一 `request_id`。
- 你在对话中纠正了一个既有结论：模型检索到对应分块或文档后更新它，不让相互冲突的版本同时存在。
- 对话触及一个全新领域且没有对应知识库：模型按需新建并写入，而不是要求你手动建库。

## 触发与边界（SYSTEM 何时生效）

- SYSTEM 规则**只在 AstrBot 已经产生正常 LLM 请求时注入**；对没有产生模型请求的消息（例如未被唤醒、未被回复的群消息）**不额外发起后台 LLM 判断**。
- 本插件注册了一个消息监听，用于记录聊天消息中**真实携带的附件**（只登记可导入的句柄，不回复、不入库、不调用模型）；它与“额外发起后台 LLM 判断”是两回事。
- 引用群聊内容时，只提取其中可核实、可复用的专业知识并保留必要的来源语境，不编造任何具体领域事实。

## 自主性、可控与停用

- 用户可编辑 `autonomy_system_prompt` 调整判断标准与入库尺度；**默认值即内置自主维护规则，清空（或仅空白）恢复内置默认**。
- 不希望自动维护时，可直接停用本插件；框架层面的**插件禁用 / 会话禁用 / 全局工具停用 / 工具权限**依然生效。
- 本插件不修改 AstrBot 的全局设置；人格无需手动勾选本插件工具，工具随正常 LLM 请求提供。

## 环境要求

- AstrBot：`>=4.28.2,<5`（见 `metadata.yaml` 的 `astrbot_version`）。
- Python：3.12+（与 AstrBot 运行环境一致）。
- AstrBot 内置 Agent（`local` 运行器）：本插件的本地工具由 AstrBot 内置 Agent 执行；聊天模型本身可以是远程 API，与运行器类型无关。
- 一个支持工具调用的聊天模型：用于在正常对话中自主判断并调用本插件工具。
- 一个可用的嵌入模型：用于知识库向量化；聊天模型不会被当作嵌入模型使用。
- 第三方 Agent 运行器（Dify / Coze / DashScope / DeerFlow 等）不执行这套本地工具，因此不适用本插件的自主维护。

## 安装

1. **插件文件夹方式**：将 `astrbot_plugin_kb_manager` 整个文件夹放入 AstrBot 的 `data/plugins/` 目录，然后在 WebUI「插件管理」中重载并启用。
2. **从仓库安装**：在 WebUI「插件管理」中选择从仓库 / URL 安装，填写 `https://github.com/Rinyin/astrbot_plugin_kb_manager`；也可以在 `data/plugins/` 目录执行 `git clone https://github.com/Rinyin/astrbot_plugin_kb_manager.git` 后重载插件。
3. **ZIP 导入**：在 WebUI「插件管理」中上传 ZIP 安装。压缩包根目录应为 `astrbot_plugin_kb_manager/`，并包含 `metadata.yaml` 与 `main.py`。
4. 插件的第三方依赖由 `requirements.txt` 声明；依赖缺失时由 AstrBot 联网安装。

## 配置

在 WebUI「插件管理 → 知识库自主运维 → 配置」中设置：

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `autonomy_system_prompt` | 文本 | 内置自主维护规则（可编辑；清空恢复默认） | 自主维护的 SYSTEM 规则正文；默认值即插件内置的完整规则。每次正常 LLM 请求都会注入它。可编辑以调整模型的判断标准与入库尺度，清空或仅空白恢复内置默认。 |
| `default_embedding_provider_id` | 字符串 | 空 | 默认嵌入模型提供商 ID，可从 `kbm_list_kbs` 返回的候选列表中获取；也可留空，由 LLM 在创建知识库时选择（恰好只有一个可用嵌入模型时自动选择，多个候选时由工具返回候选供 LLM 选择）。此处填写的是嵌入模型，不是聊天模型。 |
| `max_file_mb` | 整数 | 20 | 单个文件/会话附件大小上限（MiB）。 |
| `max_url_mb` | 整数 | 5 | 公网网页下载与提取正文的大小上限（MiB）。 |
| `attachment_ttl_minutes` | 整数 | 30 | 会话附件记录的有效期（分钟）；插件重载后记录清空。 |
| `http_timeout_seconds` | 整数 | 30 | 网页抓取总超时（秒，含重定向）。 |
| `max_concurrent_jobs` | 整数 | 3 | 后台写任务最大并发数。 |

所有整数配置必须为正整数。

## 使用示例

自主维护不需要任何命令。用户也可以直接指示模型做具体维护，例如：

- “把这段整理进知识库”
- “在知识库中搜一下‘保修政策’”
- “新建一个叫‘产品手册’的知识库”

写操作会由 LLM 自动附带 `request_id` 用于幂等重试：同一次改动重试复用同一 `request_id`，不会重复写入；用户无需手动书写。修改参数后需使用新的 `request_id`（LLM 会自行生成）。

## 工具一览（17 个）

以下工具随正常 LLM 请求提供，模型按 SYSTEM 规则自主调用，也可由用户明确要求触发；无需在人格中手动勾选：

| 工具 | 说明 |
| --- | --- |
| `kbm_list_kbs` | 列出知识库，并返回可用嵌入模型与默认项 |
| `kbm_create_kb` | 创建知识库 |
| `kbm_update_kb` | 更新知识库描述/分块参数 |
| `kbm_delete_kb` | 删除知识库及其文档 |
| `kbm_list_documents` | 分页列出文档（支持文件名过滤） |
| `kbm_read_document` | 读取文档元数据与分块 |
| `kbm_search` | 在指定知识库内检索相关分块 |
| `kbm_add_text` | 以文本内容新增文档 |
| `kbm_list_attachments` | 列出当前会话可见的近期附件（不下载） |
| `kbm_import_attachment` | 导入当前会话的附件 |
| `kbm_import_url` | 抓取公网网页正文并导入 |
| `kbm_replace_document` | 以新文本整篇替换文档 |
| `kbm_delete_document` | 删除文档 |
| `kbm_add_chunk` | 添加分块 |
| `kbm_update_chunk` | 更新分块 |
| `kbm_delete_chunk` | 删除分块 |
| `kbm_job_status` | 查询后台任务状态与进度 |

## 行为与边界

- **SYSTEM 注入**：维护规则以本插件特有的标记块追加到系统提示中；重复注入只替换该标记块，不改变模型原有的系统内容（幂等）。
- **隔离**：任务与附件按“同一会话（UMO）+ 同一发送者”隔离，其他会话或发送者不可见、不可访问；scope 始终由可信事件生成，绝不来自模型输出或用户文本。
- **附件**：只接受聊天消息中真实携带的文件；单附件默认上限 20 MiB；记录默认保留 30 分钟，插件重载后清空；不会删除平台上的原文件。
- **网页**：只允许公网 HTTP(S)，默认 5 MiB、30 秒、最多 5 次重定向；仅支持静态 HTML/纯文本正文提取，不使用 Tavily，不运行浏览器脚本；拒绝内网地址与带用户名密码的 URL。
- **替换语义**：整篇替换会生成**新的 doc_id**（不保留旧 ID）；分块更新会生成**新的 chunk_id**，文档 ID 与分块序号保持不变。旧内容保留到新内容写入成功为止；`partial`/`interrupted` 状态不能当作成功。
- **检索**：使用本插件自带的 `kbm_search`；把知识库绑定到聊天会话的 RAG 行为由 AstrBot 自身配置控制，与本插件相互独立。
- **原文保留**：AstrBot 不保留原始上传文件，检索与读出的是切分后的知识分块。
- **导入格式**：文本/文档导入以 AstrBot 原生解析器支持范围为准（如 `.md` / `.markdown` / `.txt` / `.rst` / `.adoc` / `.docx` / `.xlsx` / `.xls` / `.pdf` / `.epub` 等）；网页正文会先提取为 UTF-8 文本再导入。
- **任务**：耗时写操作超过等待时间会返回 `job_id`，用 `kbm_job_status` 查询进度；进程重启后中断的任务不会自动重放。
- **数据目录**：运行状态（任务数据库、附件缓存）位于 AstrBot 插件数据目录，与插件代码目录分离。
- **写入一致性**：不承诺与 WebUI 同时修改同一个知识库时的跨存储原子性，请避免并行写入同一知识库。
- **处理范围**：只在 AstrBot 产生正常 LLM 请求时执行 SYSTEM；对没有产生模型请求的消息不额外发起后台 LLM 判断。本插件不会修改 AstrBot 本体。
